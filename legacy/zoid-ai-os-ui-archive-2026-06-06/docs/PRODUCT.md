# Product

## Register

product

## Users

Zoid is for a solo founder, product owner, and technical operator running MaVoid work across code, agents, content, automations, notes, files, browser capture, business follow-up, products, and inbox operations. The user works in a desktop environment and needs a local operating system for deciding what matters, launching AI-assisted work, reviewing outputs, and keeping local truth separate from previews or simulated data.

## Product Purpose

Zoid is a Tauri, React, and TypeScript desktop AI operating system. It unifies daily priorities, agent runs, repositories, review gates, launch verification, content automation, files, notes, business records, products, browser captures, automations, and inbox attention into one local-first workspace. Success means the operator can see current truth, start or inspect work, resolve blockers, verify outputs, and move between linked entities without losing context or trusting fake state.

## Brand Personality

Focused, controlled, precise. Zoid should feel like a serious local command center for operational judgment, not a flashy AI demo. Its voice is direct and truthful: it separates native state from preview state, names blockers plainly, and avoids generic productivity hype.

## Anti-references

Avoid generic SaaS dashboard card grids, AI-chat novelty surfaces, decorative gradients, fake metrics, simulated records presented as truth, glassmorphism used only for decoration, over-rounded bubble UI, hero-marketing layouts, and AI-cliché copy about supercharging or transforming work. Avoid any interface that hides review gates, backend availability, data source, or verification state.

## Design Principles

1. Truth before polish: every surface must clearly distinguish native data, preview data, blocked bridge state, and verified state.
2. One operating shell: Today, Code, Agents, Notes, Content, Automations, Business, Products, Files, Browser, Inbox, and Settings should feel like parts of one desktop OS.
3. Review gates are first-class: approvals, required fixes, launch evidence, and blockers should be visible operational objects, not side notes.
4. Dense but calm: the interface should support many linked entities and statuses without becoming loud, gimmicky, or visually fragmented.
5. Local-first confidence: desktop chrome, keyboard-friendly controls, status panels, and inspectable histories should make Zoid feel reliable under real work pressure.

## Accessibility & Inclusion

Target WCAG AA contrast for text and controls. Support keyboard navigation, visible focus, readable dense data, clear status labels in addition to color, reduced-motion alternatives, and truthful empty/loading/error states. The app currently targets a desktop layout with a minimum-width shell, so responsive behavior should prioritize desktop composition, tablet-scale fallback, and no content overflow.
