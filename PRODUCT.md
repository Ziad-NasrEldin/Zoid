# Product

## Register

product

## Users

Zoid 25 is for a solo founder, product owner, and technical operator running MaVoid work across code, agents, content, automations, notes, files, browser capture, business follow-up, products, and inbox operations. The user works in a macOS desktop environment and needs a local operating system for deciding what matters, launching AI-assisted work, reviewing outputs, and keeping local truth separate from previews or simulated data.

## Product Purpose

Zoid 25 is a clean restart of the Zoid desktop AI operating system. It begins as a minimal Tauri, React, and TypeScript macOS scaffold with a navigation sidebar and blank canvas, then grows into a local-first workspace for priorities, agent runs, repositories, review gates, launch verification, content automation, files, notes, business records, products, browser captures, automations, and inbox attention. Success means the operator can see current truth, start or inspect work, resolve blockers, verify outputs, and move between linked entities without losing context or trusting fake state.

## Brand Personality

Focused, cultural, precise. Zoid 25 should feel like a serious local command center with the editorial confidence and architectural restraint of Villa Kujoyama: stark type, generous negative space, strict rules, one committed blue, and no generic AI-dashboard gloss.

## Anti-references

Avoid generic SaaS dashboard card grids, AI-chat novelty surfaces, decorative gradients, fake metrics, simulated records presented as truth, glassmorphism used only for decoration, over-rounded bubble UI, hero-marketing layouts, and AI-cliché copy about supercharging or transforming work. Avoid any interface that hides review gates, backend availability, data source, or verification state. Avoid copying Villa Kujoyama logos, photography, or proprietary assets; translate the system language instead.

## Design Principles

1. Editorial OS: use typographic hierarchy, ruled divisions, and white space before cards or decoration.
2. Blue as architecture: the committed blue carries rails, selected states, panels, and image tinting; it is not sprinkled as decoration.
3. Lists over cards: operational objects should read as structured rows with fine dividers, compact labels, dates, dots, and pill tags.
4. Truth before polish: every surface must clearly distinguish native data, preview data, blocked bridge state, and verified state.
5. Dense but calm: the interface should support many linked entities and statuses without becoming loud, gimmicky, or visually fragmented.

## Accessibility & Inclusion

Target WCAG AA contrast for text and controls. Support keyboard navigation, visible focus, readable dense data, clear status labels in addition to color, reduced-motion alternatives, and truthful empty/loading/error states. The app currently targets a desktop layout with a minimum-width macOS shell, so responsive behavior should prioritize desktop composition, tablet-scale fallback, and no content overflow.
