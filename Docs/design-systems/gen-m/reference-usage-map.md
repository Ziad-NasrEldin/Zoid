# Gen-M / Sumi-e Reference Usage Map for Zoid 25

This is a product-UI translation map, not an asset-copying plan. The references should inform tokens, motion, placement, density, and interaction motifs inside Zoid 25. Do not copy third-party artworks, photography, stamps, animations, or downloadable assets into the app unless licensing is explicitly checked and approved.

## Product stance

Zoid 25 is an operational desktop app. The references are mostly atmospheric art/portfolio sources, so the right move is controlled use:

- Use ink and brush motifs as structural accents, status signatures, transition masks, and empty-state atmosphere.
- Keep Zoid's current truth-first hierarchy: state labels, readable controls, keyboard focus, no fake data.
- Do not let painterly ornament compete with action density, text legibility, or review gates.
- Keep the existing Kujoyama cobalt architecture unless a screen is intentionally put into a monochrome/ink mode.

## Reference-by-reference recommendations

### 1. Behance — “Pagoda and blossom sakura tree”
URL: https://www.behance.net/gallery/140502127/Pagoda-and-blossom-sakura-tree

**Observed qualities**

- Delicate sumi-e / watercolor composition on a large white field.
- Thin black branches, soft gray architectural base, and selective saturated sakura red-pink.
- Small red seal/stamp gives the composition an authored, approved, ceremonial finish.
- Calm, centered, object-like illustration; more poetic than operational.

**Best Zoid uses**

1. **Content module empty states / campaign starts**
   - Use this reference when Content/OmniSocials has no active plan yet.
   - Translation: a sparse branch-like abstract line with 1–3 pink dots, not literal blossoms.
   - Copy tone: “No content rhythm selected” / “Choose a campaign lane.”

2. **Approval / publish-ready seal**
   - The red stamp idea can become a small square “approved” seal for reviewed content, final design approvals, or critique-approved states.
   - Must include text/state label; never rely on the stamp alone.

3. **Brain note clusters**
   - Branch-and-blossom pattern can represent connected notes, not a normal graph visualization.
   - Use as a quiet visual in the Brain header or empty linked-note panel.

4. **Celebratory but restrained success moments**
   - Sakura red/pink should be rare: campaign approved, content calendar published, profile completed.
   - Avoid using it as regular warning/error/status color.

**Do not use for**

- Core navigation chrome.
- Code or Automations dense tables.
- Long-running agent activity; it is too calm and final.

### 2. Behance — “Drawing PULLED BY WIND”
URL: https://www.behance.net/gallery/148666423/Drawing-PULLED-BY-WIND

**Observed qualities**

- Violent diagonal energy, wind-pulled gesture, scratchy black linework, dry brush streaks.
- A central figure almost dissolves into movement.
- Dense line bundles cross with heavy black strokes and pale pencil texture.
- Feels like interruption, acceleration, force, or an active system under load.

**Best Zoid uses**

1. **Agents running / streaming / interrupted state**
   - This is the strongest reference for Hermes/Agents motion.
   - Translation: diagonal ink streaks behind a busy session row, stop/cancel transition, or “agent is working” strip.
   - Keep it subtle and clipped to a narrow band so the chat stays readable.

2. **Command palette invocation**
   - Use a fast diagonal brush sweep behind the command palette as it opens.
   - Animation should be transform/opacity, 180–360ms, not layout width/height.

3. **Stop / cancel / rollback affordance**
   - The wind-pull gesture can represent “pulling back” an operation.
   - Use for destructive/interruptive actions only after confirmation.

4. **Automations event burst**
   - When a watcher fires or a cron job changes state, a short dry-brush flash can mark “event happened here.”
   - Pair with exact timestamp and job status.

**Do not use for**

- Idle empty states.
- Settings or provider forms.
- Persistent background decoration. It is too loud if always visible.

### 3. Behance — “Pagoda and blossom tree — oriental traditional painting”
URL: https://www.behance.net/gallery/140501035/Pagoda-and-blossom-tree-oriental-traditional-painting

**Observed qualities**

- Similar sakura/pagoda language to reference 1, but more vertical and layered.
- A stacked pagoda base under hanging blossoms; stronger hierarchy metaphor.
- Watercolor wash gives a grounded base while branches remain thin and airy.
- Red stamp reinforces authorship/completion.

**Best Zoid uses**

1. **Projects / build-order hierarchy**
   - Pagoda layering maps well to project → module → task → review structure.
   - Translation: stacked ruled tiers or nested panels, not literal pagoda illustration.

2. **Today workspace priority stack**
   - Use as a quiet “day structure” motif: one grounded base, a few active branches.
   - Good for a top-level Today overview if/when that module becomes real.

3. **Client/product archive cards**
   - A finished archived item could get a small square seal + stacked-line thumbnail treatment.
   - Use only for high-level artifacts, not every row.

4. **Profile/completion page**
   - Works for milestone/identity screens because it feels ceremonial and composed.

**Do not use for**

- Real-time agent streaming.
- Error state decoration.
- Dense repo lists.

### 8. Awwwards — Ink Effect / Johanna Arrieta
URL: https://www.awwwards.com/inspiration/ink-effect-johanna-arrieta

**Observed qualities**

- Large pale stage with centered white web canvas.
- Ink-like interactive shader/gesture across a handwritten wordmark area.
- Minimal black text, soft gray-blue atmospheric outer field, lots of silence.
- Labeled as built with hero / shader / webgl / effect / ink.

**Best Zoid uses**

1. **High-craft hero/landing moments inside app, not everyday chrome**
   - Settings/profile welcome, first-run setup, or a special Brain landing state.
   - Use as an interaction zone, not as the app's standard background.

2. **Pointer-reactive ink trail for empty canvas only**
   - A soft cursor-following ink disturbance could work in Brain canvas or a future creative/content planning canvas.
   - Must disable for dense operational work and respect reduced motion.

3. **Workspace transition shader**
   - Potentially a WebGL/canvas mask during page changes.
   - Use only if performance is proven in Tauri; fallback to CSS opacity/transform.

4. **Artifact preview reveal**
   - A generated document/image can be revealed with a soft ink dissolve.
   - Good for Content drafts and design previews.

**Avoid**

- Always-on shader effects.
- Hover effects on every row/card.
- Anything that requires WebGL just to read or operate the app.

## Best places in Zoid by module

### Agents

- Use `PULLED BY WIND` as the main motion reference for active runs, stop/cancel, streaming, and event bursts.
- Use brush-stroke Lottie only for new session creation or command accepted feedback.
- Avoid sakura/pagoda motifs except for approved review seals.

### Brain

- Use sakura/pagoda references for empty linked-note states and calm reading surfaces.
- Use dry-brush texture very lightly for note cluster identities.
- Awwwards ink effect can be explored for a future blank-canvas interaction, but not in dense note lists.

### Code

- Keep mostly current Kujoyama/editorial system.
- Use brush dividers only in code review handoff/document views.
- Use red seal motif only for `APPROVED` critique/review states.
- Avoid decorative textures behind repository lists, diffs, terminals, and branch controls.

### Automations

- Use wind/dry-brush flash for watcher-fired or cron-run events.
- Use brush dividers to separate native Hermes cron jobs from preview/fake or blocked bridge states.
- Avoid painterly empty states that make scheduled jobs feel less mechanical/trustworthy.

### Content

- Strongest fit for sakura/pagoda, paint stroke, and completion flourish.
- Use sakura red-pink as a rare campaign/published/accent color.
- Use paint reveal for generated draft previews and approved campaign cards.

### Settings / Providers

- Keep practical and calm.
- Use almost none of these except faint dividers and maybe a first-run completion flourish.
- Do not place textures behind forms or credentials.

## Implementation priority

1. **Safe system primitives first**
   - Add local CSS/SVG primitives: `ink-divider`, `dry-brush-mask`, `approval-seal`, `wind-stroke`, `paint-reveal`.
   - No external assets required.

2. **Apply to one controlled surface**
   - Recommended first test surface: Agents active-run feedback or Content empty state.
   - This prevents the whole app from becoming decorative before the motif is proven.

3. **Add motion with reduced-motion fallback**
   - Prefer CSS transform/opacity.
   - Only use Lottie/WebGL after performance and licensing checks.

4. **Critique gate before app-wide rollout**
   - Any implementation should pass feature critique because these references can easily become ornamental or reduce clarity.

## Hard rules

- Do not import Behance/Magnific/Lottie/Awwwards assets directly without explicit license approval.
- Do not replace Zoid's existing root design system yet.
- Do not use brush art as functional state unless the state is also written in text.
- Do not use tiny art-site typography for operational UI.
- Do not add always-on animations to dense workspaces.
- Do not make Code/Automations feel like a poster; they need trust first.
